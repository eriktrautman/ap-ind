What exists today

Working broadcast pages

Three. The on-air ticker (Blob-fed, deployed). The race result (B5) and the versus-2024 map (B13), which only run against the local WebSocket server; on Vercel they work in sample-data mode only.

The C and D charts

C1–C9 and D1–D11 exist as 16:9 sketches on the Graphics Data Options page, with hand-typed sample numbers. None is a page that can be put on air. The Movement Overview defaults name twelve of them, so twelve new graphics are in this plan.

Producer state

One Blob file, producer.json: pinned race ids, manual items, idle text. Written by /studio with the shared password, read by the ticker every 5 s. No notion of defaults versus local edits yet.

Data in Blob

Every race with top candidates once a minute, county units per state every ten minutes, poller status with plain-English diagnoses. Missing for the defaults: the AP Trend reports (D3, D4), a polling dataset (C7), 2024 shares (C6, D10), ranked-choice rounds (B9), per-race history (B7).

State model

One schema, three sources. The producer picks which source feeds their copy of the app; the choice is shown on every section and carried on every graphic link as ?src=.

Default

Shipped with the code

Featured races from the curated candidate index (7), featured charts B5 · B6 · B7 · B8 · B9 · B10 · B13, movement charts C1 · C6 · C7 · D1–D7 · D10 · D11, ticker = featured races, AP-call highlight on. Read-only.

Global

Shared, in Blob

What the on-air ticker and anyone else on Global uses. Written only through the safeguard dialog, which shows exactly what changes and warns if another operator published since you loaded.

Local

This browser only

Kept in the browser, never written to Blob. Starts as a copy of Global or Default. "Use global" and "Restore defaults" replace it after a warning that names what will be lost.

Selector

Which one you are on

A three-way switch in the status bar plus a banner on each section. Graphics opened from the page carry the choice; the on-air ticker stays on Global unless its URL says otherwise.

Stories

Fibonacci points. Order within an epic is build order. "After" names the story that must land first. Collision notes mark files the other sessions own.

Files edited that others own

  • studio/public/studio/: the panel is rebuilt in place (index.html, studio.js, studio.css). Anyone else editing these should stop first.
  • studio/api/producer.js: additive fields only, old fields untouched.
  • studio/public/ticker.html and ticker-queue.js: the call-highlight flag and the source parameter.
  • studio/lib/poll.js, studio/lib/ap.js: Trend reports, margin history, ranked-choice rounds, all additive.
  • public/g/feed.js, race.html, swing.html: a Blob polling path beside the WebSocket path.
  • docs/index.html, docs/nav.js: one link each.
  • studio/package.json: the build copy.

Everything else is new

  • studio/public/control.js: schema, defaults, source resolution.
  • public/g/: one file per new graphic, plus a shared national map module.
  • config/baseline-2024-federal.json and config/polls.json with the scripts that build them.
  • Staged by name, never git add -A. One commit per story or small group.
