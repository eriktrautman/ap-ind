Watch Party

A public site where every independent candidate, and anyone following them, can track their own race on election night: all 204 races with an independent or third-party candidate on the ballot, not just the seven on the broadcast.

Design v0.1 · Oct 22 2026Separate deployment from the broadcast appData: AP Elections API, one-minute cadence

1. What it is

  • Race list. Every race with an independent (204: 27 Senate, 177 House; 756 candidates), one row per race with the independent first: photos, vote counts, shares, expected vote in, status. Filter by state, office, status; sort by margin, share, or how much is in. Star races to pin them to the top (kept on the device).
  • Race page. One URL per race (/race/NE-SEN) with a small dashboard: the race summary, head-to-head bars for every candidate, a county map that fills in as counties report, with hover or tap to inspect, and the same counties as a sortable table beneath.
  • Live. The page refreshes itself every minute without a reload, and always shows "data as of", AP feed status, and how much of the expected vote is counted.
  • Phone first. Most viewers will be at a watch party holding a phone; the desktop layout is the phone layout with the county map alongside.

3. Data flow

The viewer never talks to the poller. The poller writes one small JSON file per race plus an index and a status file; the site and the viewers read those files through a CDN. Ten viewers or ten thousand cost the same. If the poller stops, the files simply stop changing and every page shows a stale "data as of" with an amber indicator.

4. Pages and API

PathContent
/Race list from index.json: one row per race with candidates (id, name, party, photo, votes, pct, winner), eevp, call status, closing time, last update. Filters, sort and stars are client-side.
/race/NE-SENRace page from race/NE-SEN.json: race summary, candidates, county units (fips, name, votes per candidate, precinctsPct, eevp), poll close, 2024 result for the same seat.
status.jsonPoller state: last successful AP fetch, AP error count, last write time, results type (test or live), races counted/called, which states' county data is fresh.
/aboutWhat the numbers mean (expected vote, AP calls, unofficial results), sources, the key notes from the broadcast graphics page.

Candidate photos

From the shared manifest (config/photos.json): official portraits for incumbents, Ballotpedia-sourced photos for others, hand-verified for the featured races, all served from the project's own CDN. Photos flagged low-confidence are shown as initials until a person clears them on the broadcast server's review page.

Status indicators

  • Feed dot in the header: green when the last successful AP fetch is under 2 minutes old, amber under 10, red beyond, with the time of the last good fetch beside it.
  • "Data as of" on every page: AP's own timestamp for the newest reporting unit in that race, which is what the viewer cares about; plus "next refresh in" counting down.
  • Per-county freshness: the county table shows AP's lastUpdated for each unit on hover, so a viewer can tell "no results" from "not updated since 8:15".
  • Test mode banner whenever the feed is AP test data, so a rehearsal can never be mistaken for the night.

Failure modes and mitigations

How hosted sites fail under loadDoes it apply hereMitigation
A function on every request: cold starts, concurrency limits, database connections exhaustedNo. Viewers read static files from the CDN; the only function is the poller, run by cron once a minute.Keep it that way: no API routes on the viewer path.
Spend cap pauses the project mid-spikeYes, if a cap is set.Raise or remove the cap before the night; alert on spend instead.
Platform outagePossible on any host.The poller also writes the files to a second store on another provider (Cloudflare R2); the page falls back to it automatically. Static site mirrored to Cloudflare Pages with DNS failover.
Slow or failing origin behind the CDNPossible.Cache headers: 60 s max-age with stale-while-revalidate, so the CDN serves the last good file instead of an error.

Capacity: roughly two requests and 60 KB per viewer per minute. Ten thousand concurrent viewers for eight hours is about 10 million requests and 300 GB, inside a Pro plan; a hundred thousand is a few hundred dollars. A load test at ten times the expected audience is part of the rehearsal week.

Recommendation: Vercel. The product is public, read-heavy and cacheable, and its cadence fits a scheduled function. Keep the broadcast server private and long-running; give the Watch Party its own AP polling on its own credentials-scoped deployment, so a traffic spike or a bug on the public site cannot touch what is on air.

7. Open questions

  1. Domain and branding: whose site is this (United Independents, the broadcast, neutral)? It changes the header, the about page, and whether candidates will share it.
  2. Which races: every race with any non-major candidate (204, includes Libertarian and Green nominees polling under 2%), or a curated list? The feed makes both trivial; the list page gets long at 204.
  3. AP rate limit for a second poller (account rep).
  4. Photos for the ~500 non-featured candidates: ship with initials where confidence is low, or hold for a human pass first?
  5. Should candidates be able to claim a race page (a link to their own site, a statement)? Adds accounts and moderation; probably not for this cycle.
